**Goal:** Turn the weather pipeline into WeatherOps — real-time weather risk and operations intelligence for Indian logistics.

**Architecture:** Ingestor (Open-Meteo live/replay + simulated hub sensors) → Kafka → Spark (validation, quarantine, dedup, 30 s windows) → Python risk engine (verdicts, risk, forecast, impact, incidents, actions) → Redis → FastAPI REST + WebSocket behind TLS → Next.js + MapLibre dashboard on Vercel. Shared pure logic lives in `weatherops/`.

**Tech Stack:** Python 3.12 (containers) / 3.13 (local), kafka-python-ng, redis-py, FastAPI, Spark 3.5.3, LightGBM, Next.js 16 + React 19, maplibre-gl, Terraform, k3s (Traefik), cert-manager.

**Spec:** `docs/superpowers/specs/2026-10-01-weatherops-design.md`

## Global Constraints

- Code that runs in containers must be valid Python 3.12; local tests run on 3.13.
- `weatherops/` imports nothing outside the standard library except `forecast.py` (numpy, lightgbm imported lazily).
- No new services: ingestor, Spark processor, engine, API, dashboard.
- All container code ships as ConfigMaps from source; no image builds. `weatherops` mounts at `/app/lib/weatherops`, service code at `/app/svc`, `PYTHONPATH=/app/lib:/app/svc`.
- Timestamps on the wire: ISO-8601 UTC with `Z`, second precision (`YYYY-MM-DDTHH:MM:SSZ`).
- Window 30 s, watermark 15 s, Kafka-sink trigger 5 s, S3 trigger 60 s, sensor interval 10 s, live poll 15 min, replay speed 120×, engine tick 10 s.
- Risk categories: Low <25 ≤ Medium <50 ≤ High <75 ≤ Critical.
- Topics: `weather-data`, `weather-quarantine`, `weather-features`, `weather-decisions`; 1 partition, 24 h.
- API is read-only, unauthenticated, CORS `*` for GET.
- Open-Meteo: ≤10 variables per request; credit "Weather data by Open-Meteo.com (CC BY 4.0)".
- Commit after each task; messages end with the Co-Authored-By line.

## Review Focus

1. Open-Meteo returns `{"error": true}`, HTTP 429, or nulls for one city → ingestor keeps running, holds last values, emits nulls as missing values (Task 3, Task 6).
2. Fresh bring-up, Redis empty, no windows yet → API `/api/snapshot` returns a valid empty snapshot and the dashboard renders empty states (Task 16, Task 20).
3. Ingestor restarts and `seq` restarts at 0 → engine treats it as a reset, never counts negative gaps as missing (Task 14).
4. A WebSocket client that stops reading → dropped without blocking broadcast to others (Task 16).
5. Every sensor at a hub suspect or stale → hub falls back to the city reference, not Low-by-default (Task 14).

## Shared shapes

Used across tasks; field names are exact.

- **Conditions** (dict): `temperature_c, humidity_pct, rain_mmph, wind_kmph, gust_kmph, visibility_m, pressure_hpa, rain_24h_mm` (any may be `None`).
- **Reading** (dict): spec "Reading v2".
- **Window** (dict): spec "Feature window"; timestamps as ISO strings.
- **Assessment** (dict): `score:int, category:str, hazard:str|None, factors:{rain,wind,heat,fog: float}, inputs:dict, unusual:bool, developing:bool, forecast_score:int|None, forecast_category:str|None`.
- **Verdict** (dict): `status: ok|weather_event|sensor_suspect|stale, reason:str|None, field:str|None`.
- **Action** (dict): `id, priority: P1|P2|P3, owner, text, assets:list[str], because:str`.
- **Incident** (dict): `id, region, region_name, hazard, status: open|escalated|resolved, category, opened_at, resolved_at, score, peak_score, routes, hubs, deliveries_at_risk, peak_deliveries, actions, timeline:[{at,status,hazard,reason}]`.

### Task 4: sources, scenarios, events

**Files:** Create `ingestor/sources.py`, `ingestor/scenarios.py`, `ingestor/events.py`, `ingestor/tests/test_sources.py`.

**Interfaces (produces):**
- Common source API:
  - attributes `source: str`, `scenario: str | None`, `speed: float`, `sensor_smoothing_s: float`
  - `tick(now) -> datetime` (advances clock, polls if due, returns `observed_at`)
  - `reference(city_id, observed_at) -> Conditions | None`
  - `at_point(station, observed_at) -> Conditions | None` (default `reference(station.city_id, …)`)
  - `reference_due(now) -> bool`
- `LiveSource(network, fetch_current=…, fetch_hourly=…, poll_minutes=15, backfill_hours=3, speed=120)`: on first tick fetches the last `backfill_hours` hourly + current; clock runs from `now − backfill` at `speed` until it reaches real time, then follows real time. `reference_due` true every tick during backfill, then once after each successful poll. Poll failure → log, keep timeline, retry after `min(poll, 2^k min)`. `sensor_smoothing_s = 300`.
- `ReplaySource(network, event, fetch_hourly=…, speed=120)`: fetches `[event.start − 3 h, event.end]`; `observed_at = start − 3 h + (now − t0) × speed`; past `event.end` restarts (`t0 = now`). `reference_due` always true. `sensor_smoothing_s = 0`.
- `SimSource(network, scenario, seed=0)`: `observed_at = scenario.start + (now − t0) × scenario.speed`, loops after `scenario.duration`. `at_point` evaluates hazards at the station coordinates. `sensor_smoothing_s = 0`.
- `scenarios.Scenario(id, start, speed, duration, cells, fogs, heats)`; `StormCell(track: [(lat, lon)], start_offset, duration, radius_km, peak_rain_mmph, peak_gust_kmph)`; `FogBank(center, radius_km, start_offset, duration, min_visibility_m)`; `HeatDome(center, radius_km, anomaly_c)`. `SCENARIOS` dict with `storm-chennai` (cell crossing Sriperumbudur hub into Chennai), `fog-north` (Delhi NCR + Lucknow), `heatwave-north`, `monsoon-mumbai`.
- `scenarios.baseline(city, observed_at, seed) -> Conditions` (diurnal temp by latitude, humidity, light wind, visibility 15 km, pressure 1008).
- Hazard intensity profile: grow 25 % / peak 50 % / decay 25 % of duration; spatial falloff `exp(−(d/radius)^2)`.
- `events.Event(id, name, start, end, region_city_ids, speed)`; `EVENTS` dict (finalised in Task 26; seed with `michaung-2023` 2023-12-03T00Z → 2023-12-05T00Z).
- `make_source(mode, scenario, network, **cfg)` factory.

### Task 5: sensors and faults

**Files:** Create `ingestor/sensors.py`, `ingestor/faults.py`, `ingestor/tests/test_sensors.py`, `ingestor/tests/test_faults.py`.

**Interfaces (produces):**
- `SensorBank(sensors, rand, micro_rate_per_hour=1/6)`; `read(station, base: Conditions, now, smoothing_s) -> Conditions`. Per-sensor static bias (temperature ±0.5, pressure ±0.5); noise σ: temp 0.3, humidity 2, wind 1.5, gust 2.5 (gust ≥ wind), pressure 0.3; rain `max(0, base × (1 + N(0, 0.1)))`; visibility × (1 + N(0, 0.05)) capped 30 000. First-order lag toward base with time constant `smoothing_s` (0 = no lag). Hub micro-event: Poisson per hub, 10–25 min, bell-shaped intensity: rain +10–40 mm/h, gust +15–30, temperature −2–4, visibility × 0.5; each sensor ±20 %. Exposes `micro_events` ground truth.
- `FaultInjector(rand, rate_per_sensor_hour=0.25, interval_s=10)`; `apply(station_id, reading, now) -> list[tuple[datetime, dict]]`; `log` list of `(at, station_id, kind)`. Kinds and weights: spike .20, stuck .15, drift .10, dropout .15, invalid .15, duplicate .15, delayed .10. Episodes: stuck 5–30 min (freeze the measurement fields at episode start), drift 30–60 min (temperature +0.1–0.2 °C/min), dropout 2–15 min (returns `[]`). Single-shot: spike (one field: temperature ±15–25, rain +80–200, gust +60–120, visibility × 0.05), invalid (humidity 140 | temperature −99 | rain −5 | `station_id` removed), duplicate (same dict twice, second 0–5 s later), delayed (send at now + 20–120 s).
- `force(station_id, kind, now)` starts an episode deterministically (tests, scenarios).

- [ ] Step 1: tests first (seeded `random.Random`):
  - smoothing 300 s: base steps 20 → 30, after 300 s value ≈ 26.3 ±0.8 (1 − e^-1), noise aside (set noise via a zero-sigma flag `noise=False`).
  - smoothing 0: value tracks base ± noise (σ bounds over 1000 draws).
  - micro-event on hub H raises rain on every sensor of H and on no sensor of another hub.
  - rain never negative; gust ≥ wind.
  - faults: forced `duplicate` → two identical dicts; `delayed` → one message with send time ≥ now + 20 s; `dropout` → `[]` for subsequent calls within duration, readings resume after; `stuck` → measurement fields constant across calls for the episode; `invalid` → `schema.validate` returns a reason; `spike` → exactly one call altered.
  - rate: 10 000 calls at rate 0.25/h, 10 s interval → episodes ≈ 6.9 (±5) — deterministic with seed.
- [ ] Step 2: fail → implement → pass.

### Task 10: risk
